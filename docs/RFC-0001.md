# RFC-0001: meridian-lexicon v0.1

Status: living spec. Tracks `lexicon-core` 0.1. Not a standards-track document.

## 1. Purpose

Replace NICKA's secret-list uniqueness with keyed derivation and an append-only
ledger. Anyone with an authority public key can verify a name was fairly minted
from the published pool. Nobody without the secret can predict the next name.

## 2. Names

| `NameType` | Form | Example |
|------------|------|---------|
| `nickname` | two words, space, uppercase | `GRANITE SPIRE` |
| `codeword` | one word | `OXIDE` |
| `cryptonym` | digraph \|\| word, no space | `AELANTERN` |
| `sap` | digraph or trigraph | `TK`, `HCS` |
| `exercise` | two words from the exercise pools | `COPPER RELAY` |

Normalization: uppercase, collapse ASCII whitespace. The normalized form is the
ledger uniqueness key. Types share one namespace — a nickname occupies the
string against code words and exercise terms.

## 3. Minting algorithm

### 3.1 Keys

Each issuing authority holds one Ed25519 seed (RFC 8032 §5.1.5). The same seed
is the ECVRF secret key. Rotation is a `key_rotated` ledger event signed by the
old key. Silent rotation is invalid.

**Split authority (HSM profile).** The OSS profile uses one `Authority` (one
seed) as both `Signer` and `VrfSigner`. A FIPS 140-3 / HSM-backed `ic`
profile cannot: an HSM (PKCS#11) does not export the raw scalar. `Minter`
takes `&dyn VrfSigner` and `&dyn Signer` independently — the HSM profile
is a config swap, not a rewrite.

- **Event-signing key:** held in the HSM. The `Signer` trait drives it; no raw export.
- **VRF seed:** a separate 32-byte secret, envelope-encrypted at rest under an
  HSM-resident KEK. The `VrfSigner` trait is the prove seam;
  `RemoteVrfSigner` (`--features hsm`) talks to a local-socket proxy that
  holds the seed. Custody of that seed (who unwraps the envelope, where the
  proxy runs) is the accreditor's responsibility, outside the ledger.

Two secrets, two custody streams, one authority id. A `key_rotated`
event rotates the event-signing key (HSM-resident) and names `new_alg`; the
VRF seed is rotated by a separate, offline ceremony and is **not** recorded
on the ledger (the VRF public key is not an input to verification — only the proof and beta are). This is a deliberate asymmetry: the ledger authenticates who signed; the VRF secret's custody is an operational concern, not a ledger event.

The `Signer` trait does not close the VRF. `VrfSigner` does. Seed custody
stays outside the ledger regardless.

### 3.2 VRF

Ciphersuite: **ECVRF-EDWARDS25519-SHA512-TAI**, RFC 9381 suite `0x03`.
Test vectors: RFC 9381 Appendix B.3 Examples 16–18.

TAI encode-to-curve is not constant-time in `alpha`. `alpha` is
`(authority, type, pool, seq, nonce)` — not a secret identity.

### 3.3 Alpha encoding

```
"MERIDIAN-MINT-v1" || 0x00
|| u16le(len(authority_id)) || authority_id
|| u8(name_type_tag)
|| u16le(len(pool_id)) || pool_id
|| u64le(sequence) || u32le(nonce)
```

Tags: nickname=1, codeword=2, cryptonym=3, sap=4, exercise=5.

`sequence` is the ledger `next_seq` captured at the start of a mint attempt
loop. Nonce starts at 0 and increments on lint reject or collision.

### 3.4 Index derivation

`beta` is 64 bytes. For each pool size `n_i`, index `i` is
`u64le(beta[8*i .. 8*i+8]) % n_i`.

Two-word names use two indices. Cryptonyms use (digraph index, word index).
`--digraph` overrides only the digraph index; the word index remains VRF-bound
and is what `verify_mint` checks.

### 3.5 Loop

```
sequence = ledger.next_seq()
nonce = 0
loop:
    (pi, beta) = VRF_prove(sk, alpha(sequence, nonce))
    name = compose(pools, indices(beta))
    if lint rejects: append Attempt(lint); nonce++; continue
    if ledger contains name (issued|retired|revoked):
        append Attempt(collision); nonce++; continue
    append Issued(...); stop
```

Attempts are first-class ledger events. Collisions are observable.

Max attempts default 64. Exhaustion is a hard error.

### 3.6 Program binding

`MintRequest` may carry `program_pid` and optional `compartment_id`.
`--classification` on a program-bound codeword or cryptonym is ignored;
the marking is derived from the program (see §5). Nickname, exercise, and
SAP designator names may record the pid but stay U/CUI (see §5.2).

A free-standing mint (no program) stores `--classification` on the name
as before.

## 4. Classification markings

Every issued name carries a CAPCO marking. The marking is a typed struct,
not a free-form string. For free-standing names it is signed and hashed
into the `Issued` event. For program-bound codewords and cryptonyms the
event still carries a mint-time marking, but read paths re-derive from
current program controls (see §5.1). Canonical bytes of the marking sort
by tag — display order is not bound, so event hashes stay stable if the
renderer changes.

Display order is `CLASSIFICATION // SCI // SAR // AEA // FGI // DISSEM`.

- SCI is a bare designator (`TK`, not `SCI/TK`). Same-kind SCI tokens
  group comma-separated under one slot (`TK,HCS`).
- SAP is `SAR-<pid>` or `SAR-<pid>-<compid>` (hyphen, not slash). SAR
  tokens are composite and do not group.
- Two profiles: `display_banner()` spells out the level (`TOP SECRET`)
  and full dissem names (`NOFORN`); `display_portion()` abbreviates
  (`TS`, `NF`). The `Display` impl is portion form. The CLI parenthesizes
  portion marks and uses banner form on page headers (`CLASSIFICATION:
  <banner>`).

Parse enforces CAPCO order and rejects a bare `SCI` token, a slash-form
SAR, and a designator not in the bundled register. `from_stored` is
lenient: it accepts legacy `SCI/<dg>` and `SAP/<dg>` and out-of-order
tokens so old ledger rows re-parse and re-display in the new grammar.
Lenient parse is permanent; canonical bytes are the trust anchor, not
the stored string.

`validate()` checks: no bare SCI, SAR uses hyphen, SCI/SAR designators
in `sci_register.json` (sample until the accreditor ships the real list).
Classified nicknames are refused at mint, not here.

The ledger container stays unclassified. The marking is metadata about
the name. Display-name uniqueness is one namespace across all markings.

## 5. Programs

A Program is the source of truth for a SAP. Names bind to a Program and
optionally a Compartment. Markings for bound codewords/cryptonyms are
computed at read time from current controls.

```
Program QSV (unack, TS)
  sci: TK
  dissem: NOFORN
  Compartment HOL (sci: TK)
    codeword HOLLERED  →  TS//TK//SAR-QSV-HOL//NOFORN
  nickname DILIGENTLY IMPRESSED  →  U
```

### 5.1 Entities

Materialized from signed events (same append path as `Issued`):

| entity | fields |
|--------|--------|
| Program | `pid` (unclassified trigraph), `nickname` (two-word, U), `codeword` (one-word, optional, classified), `sap_type` (`acknowledged` / `unacknowledged` / `waived`), `level`, `authority_id` |
| ProgramControl | `(program_pid, kind, value)` where kind is `sci` / `dissem` / `aea` / `fgi` |
| Compartment | `(program_pid, id)`, nickname, optional codeword, optional `parent_id` |
| CompartmentControl | `(program_pid, compartment_id, kind, value)` — extra SCI on a compartment, e.g. TK only on sensors |

Compartment nicknames and codewords are steward-assigned (not VRF-minted)
but are uniqueness-checked against the global display-name namespace
(`Ledger::is_display_name_taken`) at add time — they share the namespace
with issued names, so a compartment nickname cannot collide with an
issued nickname or another compartment's name.

`derive_marking(program, compartment?)`:

- level from the program
- SCI = program.sci concatenated with compartment.sci (deduped)
- SAR designator = `pid` or `pid-compid`
- AEA / FGI / dissem from the program only
- `WAIVED` is derived when `sap_type = waived` (placed before other
  dissem controls, e.g. `//WAIVED//NOFORN`); it is a typed caveat, not
  operator-entered

### 5.1.1 Banner profiles and roll-up

`render_marking(program, compartment?, profile)` renders a single
slice (or the standing banner). `render_roll_up(program, compartments[],
profile)` renders a document containing several slices.

CAPCO roll-up contract — one program, sibling compartments
hyphenated to the PID and separated by **spaces** (alphanumeric order).
`SAR-` is not repeated per slice; `//` does not separate siblings. SCI
appears in the banner only if a slice **in this document** carries it.

```
standing (no slices):     TOP SECRET//SAR-DILIGENTLY IMPRESSED//NOFORN
CAPCO short, all slices:   TOP SECRET//TK//SAR-QSV-HOL PER SEN TEV//NOFORN
DoD, all slices:          TOP SECRET//TK//SAR-DILIGENTLY IMPRESSED-HOL PER SEN TEV//NOFORN
propulsion only:           TOP SECRET//SAR-QSV-PER//NOFORN   (no TK)
portion:                  (TS//TK//SAR-QSV-HOL PER SEN TEV//NF)
```

`program show` prints the **standing** banner (program record, no
slices), not a fake "everything QSV has ever owned" compilation. Roll-up
is explicit: `lexicon program banner --pid QSV [--slices HOL,PER,SEN,TEV]
[--profile dod|capco]`. The DoD profile swaps the PID for the program
nickname; compartment **IDs** stay (compartment nicknames contain
spaces and would be ambiguous between siblings).

### 5.1.2 Per-compartment level

A compartment may carry a `level` lower than the program (e.g. TEV flight-
test procedures at S). A single-slice document takes the slice's level;
a multi-slice roll-up takes the max of the included slices' levels. The
program level is not a floor — a TEV-only memo is `S//SAR-QSV-TEV//NF`
even when the program is TS.

### 5.1.3 Program-scoped names

`lexicon program names --pid QSV` lists every name belonging to a program:
the PID, program nickname, program codeword, each compartment's nickname
and codeword, and VRF-minted names bound to it. The steward-assigned names
(PID, nickname, codewords) are not in the `names` table and so do not
appear in `ledger names`; this command is the program-scoped lexicon view.

A `program_controls_changed` event re-derives every bound codeword and
cryptonym retroactively. That is intentional: the program is the source
of truth, and the event log is the audit trail. A name's displayed
marking reflects **current** program controls, not mint-time controls.
Flag this for the AO.

`Issued.program_pid` and `compartment_id` are names-index only. They are
not in `canonical_bytes`, so existing Issued hashes stay valid.

`aggregate_marking` derives for every name that carries a `program_pid`
(including nicknames that display as U) and parses the stored string for
free-standing names. A ledger that holds only a program-bound nickname
still aggregates to the program marking. The join is O(N) at read; fine
for the reference impl.

### 5.2 Nickname-stays-U

If `name_type` is `nickname`, `exercise`, or `sap`, mint refuses a
marking level above `U`. These names may record `program_pid`; their
own marking stays U. Only `codeword` and `cryptonym` derive a classified
marking from the program. (CUI is a control, not a classified level;
nicknames that need CUI handling are a separate workflow, not a marking
on the nickname string.)

### 5.3 Schema

SQLite `PRAGMA user_version` 3 (forward-only, same migrate path as v1/v2).
This is **not** event-prefix v3 (that remains the PQ valve, §12).

New tables: `programs`, `program_controls`, `compartments`,
`compartment_controls`. `names` gains nullable `program_pid` and
`compartment_id`. `names.marking` is kept for free-standing names; it
is unused at read for program-bound codewords/cryptonyms.

Event kinds `program_created`, `compartment_added`,
`program_controls_changed` (canonical tags 6/7/8) carry the full delta
and are signed and Merkle-hashed like `Issued`.

## 6. Ledger

SQLite, append-only `events` table (UPDATE/DELETE triggers abort).

Event kinds: `issued`, `retired`, `revoked`, `key_rotated`, `attempt`,
`program_created`, `compartment_added`, `program_controls_changed`.

Canonical bytes are a fixed-order length-prefixed encoding prefixed
`MERIDIAN-EVENT-v2\0` — not JSON. `event_hash = SHA-256(canonical)`.
Ed25519 signature is over `canonical`. v2 binds operator attribution.
Event-prefix v3 is the PQ valve (see §12). Kind tags 1–5 are unchanged.

Merkle tree (RFC 6962 / Certificate Transparency):

```
leaf = SHA-256(0x00 || event_hash)
node = SHA-256(0x01 || left || right)
```

An unpaired node at a level is promoted, not duplicated.

`inclusion_proof(seq)` is against the current tree. `ledger verify` recomputes
hashes, checks sequence continuity, and checks the name index.

Retired and revoked names remain in `names` with a non-issued status.
Reissue is refused. That is the 50-year quarantine, locally.

Signed snapshots: `MERIDIAN-ROOT-v1\0 || root || u64le(leaf_count) || rfc3339`.

## 7. Style linter

Rule interface + shipped core ruleset. External hooks (`trademark`,
`pop_culture`, `living_person`) are `Option<fn>` stubs — wire a real DB later.

Shipped reject rules: blocklist, pop-culture sample (incl. Vault 7 leftovers),
trademark sample, banned historical pairs (`BLUE SPOON`, `INFINITE JUSTICE`, …),
JANAP-119A Table II call-sign words, same-word pairs, meaning-leak tokens,
transliteration flags on pool entries (`word\tunsafe=ru`).

Euphony: reject words shorter than 3 letters except `sap` tokens; warn on
harsh consonant runs and rhyming pairs. Warns do not block mint.

## 8. Agency allocation

NICKA letter-blocks, encoded as `first_letters` on each agency. First-word
pools are sliced before indexing so the VRF never lands outside the block.

Nickname, codeword, and cryptonym words are derived from
`crates/lexicon-pools/data/crosswd.txt`: ASCII letters, length 4–10, regular
plurals dropped if the stem is present, then the single-word linter.
Exercise terms use the same filtered crossword; the type tag is the
namespace, not a second word list. Pool id: `lexicon-pools-v4`.

JANAP collision uses `JANAP_119A_Table_II.tsv` (word / first_digraph /
second_digraph). Rows with no digraph (`COB`) are skipped. A minted token
in that word set is a reject. Table I and third-party CSV extracts are not
inputs.

Digraphs in `crates/lexicon-pools/data/digraphs.md` are open-record
reconstructions (Church Committee, FOIA, Family Jewels, Plausible Denial).
They are historical attributions, not operational assignments.

## 9. Verify

`verify_mint`:

1. ECVRF verify `(pk, alpha, pi) -> beta`
2. `beta` matches the recorded output
3. Indices match (cryptonym: word index only if digraph was overridden)
4. `compose(pools, indices) == name`

`verify_issued` checks the mint-time inclusion receipt is internally valid,
then re-proves the same leaf against the live tree. Roots will not match after
later appends — that is expected. The leaf hash must.

## 10. CLI

```
lexicon key generate --agency DIA
lexicon mint --type nickname|codeword|cryptonym|sap|exercise --agency DIA
lexicon mint --type cryptonym --agency CIA --digraph AE
lexicon mint --type codeword --agency DIA --program QSV --compartment HOL
lexicon program create --pid QSV --nickname "DILIGENTLY IMPRESSED" \
    --sap-type unack --level TS --agency DIA --sci TK --dissem NOFORN
lexicon program compartment add --program QSV --id HOL --nickname HOLLERED --sci TK
lexicon program controls add|remove --program QSV [--compartment HOL] --sci SI
lexicon program list | show --pid QSV
lexicon verify --file minted.json [--ledger]
lexicon check --name "BLUE SPOON"
lexicon ledger verify | root [--sign --agency DIA] | names
lexicon pool inspect [--agency DIA] [--type nickname]
lexicon retire --name "..." --agency DIA --reason completed
lexicon revoke --name "..." --agency DIA --reason compromised
```

Default `--data-dir .meridian`.

Signed events bind an OS-session claim: `whoami`, hostname, and
`/etc/machine-id` (Darwin: `IOPlatformUUID`). IP is not collected. There
are no `--user` / `--host` / `--ip` / `--hwid` flags — those were a
forgery path. A debug-only `--allow-env-identity` honors `LEXICON_USER`
/ `LEXICON_HOST` for test harnesses; release builds omit the flag and
ignore those variables.

This is a claim, not an attestation. The strings are signed into
canonical so they cannot be altered after the fact, but they are not
cryptographically bound to a person. PIV/CAC binding is the HSM profile
(future). AU-10 non-repudiation is deferred until then.

Page banners use the banner profile (spelled-out). Per-name lines and
lookup use the portion profile, parenthesized. `--classification` floors
the page banner; it does not lower it below the content max.

## 11. Federation (not built)

v1 is single-authority. Cross-node uniqueness is a protocol, not an impl.

Sketch, so a later crate cannot "just CRDT it":

1. **Pre-commit.** Before `Issued` becomes visible, the minter broadcasts
   `Intent { name, alpha, pi, deadline }` to peer authorities.
2. **Quorum.** A name is committed only after a configured quorum of
   currently-online peers signs `NoCollision` against their ledgers.
   Offline peers reconcile on reconnect.
3. **Loser-recall.** If two air-gapped nodes issue the same name, the
   lower `(authority_id, sequence, nonce)` tuple (lexicographic) wins.
   The loser emits `Revoked { reason: "federation-collision" }` and the
   name stays quarantined. The loser's already-disseminated name is
   aliased in a `Superseded` event — recall, not hope.
4. CRDTs can merge *attempt* and *event* sets. They cannot invent
   uniqueness. Uniqueness is the quorum + recall rule.

50-year horizon: retired/revoked stay in the name index forever. There is
no reuse. The math in the research note (birthday bound on two-word pools)
is why this is a ledger rule, not a social one.

## 12. Profiles and crypto migration

| profile | now | later |
|---------|-----|--------|
| `oss` (this crate) | Ed25519 + SHA-256 via rustcrypto; ECVRF-ed25519-TAI (SC-13(2), outside any FIPS module); bundled SQLite | — |
| `ic` (`--features fips`) | SHA-256, Ed25519, ML-DSA via AWS-LC FIPS 140-3 (`aws-lc-rs`). ECVRF remains SC-13(2) — no validated module implements it; the AO accepts this in the SSPP. `--approved-mode` plus the `STATUS` line on `ledger verify` make the boundary machine-visible. | ML-KEM (FIPS 203) for transport. PQ VRF suite TBD. PIV/CAC binds the user claim (AU-10); the OSS profile records an OS-session claim only. |

Event prefix `MERIDIAN-EVENT-v2` is current (carries attribution).
`v3` is the compatibility valve for a PQ signature scheme: a `key_rotated`
that names the new algorithm plus a prefix bump. `v1` is historical
(pre-attribution) and is not produced by this binary.

## 13. Anti-goals

Lexicon stores no intelligence content, makes no targeting decisions, and
does not mint without a human-held authority key. It does not resolve
deconfliction — that is `meridian-graph`. It does not bind a PIV/CAC
identity; that waits on the HSM profile.

## 14. Test vectors

RFC 9381 Appendix B.3 is the VRF gate. See `lexicon-core` `vrf::tests`.
If those fail, nothing else matters.
