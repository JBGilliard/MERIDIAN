# RFC-0001: meridian-lexicon v0.1

Status: living spec. Tracks `lexicon-core` 0.1. Not a standards-track document.

## 1. Purpose

Replace NICKA's secret-list uniqueness with keyed derivation and an append-only
ledger. Anyone with an authority public key can verify a name was fairly minted
from the published pool. Nobody without the secret can predict the next name.

## 2. Names

| `NameType` | Form | Example |
|------------|------|---------|
| `nickname` | two words, space, uppercase | `GRANITE SPIRE` |
| `codeword` | one word | `OXIDE` |
| `cryptonym` | digraph \|\| word, no space | `AELANTERN` |
| `sap` | digraph or trigraph | `TK`, `HCS` |
| `exercise` | two words from the exercise pools | `COPPER RELAY` |

Normalization: uppercase, collapse ASCII whitespace. The normalized form is the
ledger uniqueness key. Types share one namespace — a nickname occupies the
string against code words and exercise terms.

## 3. Minting algorithm

### 3.1 Keys

Each issuing authority holds one Ed25519 seed (RFC 8032 §5.1.5). The same seed
is the ECVRF secret key. Rotation is a `key_rotated` ledger event signed by the
old key. Silent rotation is invalid.

### 3.2 VRF

Ciphersuite: **ECVRF-EDWARDS25519-SHA512-TAI**, RFC 9381 suite `0x03`.
Test vectors: RFC 9381 Appendix B.3 Examples 16–18.

TAI encode-to-curve is not constant-time in `alpha`. `alpha` is
`(authority, type, pool, seq, nonce)` — not a secret identity.

### 3.3 Alpha encoding

```
"MERIDIAN-MINT-v1" || 0x00
|| u16le(len(authority_id)) || authority_id
|| u8(name_type_tag)
|| u16le(len(pool_id)) || pool_id
|| u64le(sequence) || u32le(nonce)
```

Tags: nickname=1, codeword=2, cryptonym=3, sap=4, exercise=5.

`sequence` is the ledger `next_seq` captured at the start of a mint attempt
loop. Nonce starts at 0 and increments on lint reject or collision.

### 3.4 Index derivation

`beta` is 64 bytes. For each pool size `n_i`, index `i` is
`u64le(beta[8*i .. 8*i+8]) % n_i`.

Two-word names use two indices. Cryptonyms use (digraph index, word index).
`--digraph` overrides only the digraph index; the word index remains VRF-bound
and is what `verify_mint` checks.

### 3.5 Loop

```
sequence = ledger.next_seq()
nonce = 0
loop:
    (pi, beta) = VRF_prove(sk, alpha(sequence, nonce))
    name = compose(pools, indices(beta))
    if lint rejects: append Attempt(lint); nonce++; continue
    if ledger contains name (issued|retired|revoked):
        append Attempt(collision); nonce++; continue
    append Issued(...); stop
```

Attempts are first-class ledger events. Collisions are observable.

Max attempts default 64. Exhaustion is a hard error.

## 4. Ledger

SQLite, append-only `events` table (UPDATE/DELETE triggers abort).

Event kinds: `issued`, `retired`, `revoked`, `key_rotated`, `attempt`.

Canonical bytes are a fixed-order length-prefixed encoding prefixed
`MERIDIAN-EVENT-v1\0` — not JSON. `event_hash = SHA-256(canonical)`.
Ed25519 signature is over `canonical`.

Merkle tree (RFC 6962 / Certificate Transparency):

```
leaf = SHA-256(0x00 || event_hash)
node = SHA-256(0x01 || left || right)
```

An unpaired node at a level is promoted, not duplicated.

`inclusion_proof(seq)` is against the current tree. `ledger verify` recomputes
hashes, checks sequence continuity, and checks the name index.

Retired and revoked names remain in `names` with a non-issued status.
Reissue is refused. That is the 50-year quarantine, locally.

Signed snapshots: `MERIDIAN-ROOT-v1\0 || root || u64le(leaf_count) || rfc3339`.

## 5. Style linter

Rule interface + shipped core ruleset. External hooks (`trademark`,
`pop_culture`, `living_person`) are `Option<fn>` stubs — wire a real DB later.

Shipped reject rules: blocklist, pop-culture sample (incl. Vault 7 leftovers),
trademark sample, banned historical pairs (`BLUE SPOON`, `INFINITE JUSTICE`, …),
JANAP-119/ACP-119 sample call signs, same-word pairs, meaning-leak tokens,
transliteration flags on pool entries (`word\tunsafe=ru`).

Euphony: reject words shorter than 3 letters except `sap` tokens; warn on
harsh consonant runs and rhyming pairs. Warns do not block mint.

## 6. Agency allocation

NICKA letter-blocks, encoded as `first_letters` on each agency. First-word
pools are sliced before indexing so the VRF never lands outside the block.

Nickname, codeword, and cryptonym words are derived from
`crates/lexicon-pools/data/crosswd.txt`: ASCII letters, length 4–10, regular
plurals dropped if the stem is present, then the single-word linter.
Exercise terms stay a separate curated list. Pool id: `lexicon-pools-v2`.

Digraphs in `crates/lexicon-pools/data/digraphs.md` are open-record
reconstructions (Church Committee, FOIA, Family Jewels, Plausible Denial).
They are historical attributions, not operational assignments.

## 7. Verify

`verify_mint`:

1. ECVRF verify `(pk, alpha, pi) -> beta`
2. `beta` matches the recorded output
3. Indices match (cryptonym: word index only if digraph was overridden)
4. `compose(pools, indices) == name`

`verify_issued` checks the mint-time inclusion receipt is internally valid,
then re-proves the same leaf against the live tree. Roots will not match after
later appends — that is expected. The leaf hash must.

## 8. CLI

```
lexicon keygen --agency DIA
lexicon mint --type nickname|codeword|cryptonym|sap|exercise --agency DIA
lexicon mint --type cryptonym --agency CIA --digraph AE
lexicon verify --file minted.json [--ledger]
lexicon check --name "BLUE SPOON"
lexicon ledger verify | root [--sign --agency DIA] | names
lexicon pool inspect [--agency DIA] [--type nickname]
lexicon retire --name "..." --agency DIA --reason completed
lexicon revoke --name "..." --agency DIA --reason compromised
```

Default `--data-dir .meridian`.

## 9. Federation (not built)

v1 is single-authority. Cross-node uniqueness is a protocol, not an impl.

Sketch, so a later crate cannot "just CRDT it":

1. **Pre-commit.** Before `Issued` becomes visible, the minter broadcasts
   `Intent { name, alpha, pi, deadline }` to peer authorities.
2. **Quorum.** A name is committed only after a configured quorum of
   currently-online peers signs `NoCollision` against their ledgers.
   Offline peers reconcile on reconnect.
3. **Loser-recall.** If two air-gapped nodes issue the same name, the
   lower `(authority_id, sequence, nonce)` tuple (lexicographic) wins.
   The loser emits `Revoked { reason: "federation-collision" }` and the
   name stays quarantined. The loser's already-disseminated name is
   aliased in a `Superseded` event — recall, not hope.
4. CRDTs can merge *attempt* and *event* sets. They cannot invent
   uniqueness. Uniqueness is the quorum + recall rule.

50-year horizon: retired/revoked stay in the name index forever. There is
no reuse. The math in the research note (birthday bound on two-word pools)
is why this is a ledger rule, not a social one.

## 10. Profiles and crypto migration

| profile | now | later |
|---------|-----|--------|
| `oss` (this crate) | Ed25519 + ECVRF-ed25519-TAI, SHA-256 Merkle, bundled SQLite | — |
| `ic` | same algorithms, FIPS 140-3 module boundary | ML-DSA (FIPS 204) for event signatures; ML-KEM (FIPS 203) for transport. VRF suite TBD — no NIST VRF. Documented as a swap of `Authority::sign` / TLS, not a ledger-format break if we version the event prefix. |

Event prefix `MERIDIAN-EVENT-v1` is the compatibility valve. A PQ signature
scheme gets `v2` and a `key_rotated` that names the new algorithm.

## 11. Anti-goals

Lexicon stores no intelligence content, makes no targeting decisions, and
does not mint without a human-held authority key. It does not resolve
deconfliction — that is `meridian-graph`.

## 12. Test vectors

RFC 9381 Appendix B.3 is the VRF gate. See `lexicon-core` `vrf::tests`.
If those fail, nothing else matters.
