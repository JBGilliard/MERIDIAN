# Provenance

How MERIDIAN artifacts trace back to source — for evaluators, accreditors, and incident response.

## Source repository

- **Public tree:** UNCLASSIFIED reference implementation and sample data.
- **License:** Apache-2.0 (see `LICENSE`).
- **Spec:** [RFC-0001](RFC-0001.md) tracks `lexicon-core` 0.1 behavior.

Sample pool files are explicitly non-authoritative:

- `crates/lexicon-pools/data/sci_register.json` — `"sample": true`
- `crates/lexicon-pools/data/agencies.json` — agency IDs reflect public existence; not live program-to-codeword facts
- `historical_cryptonyms.txt` — declassified/public-source reject list, not live inventory

## Release binary provenance

| Input | Record |
|-------|--------|
| Git commit | Tag or `git rev-parse HEAD` at build time (adopter records locally) |
| Toolchain | `rust-toolchain.toml` → rustc 1.85.0 |
| Lockfile | `Cargo.lock` (committed; `--locked` builds) |
| Features | Document `default`, `highside`, `fips`, `pq`, `hsm` as built |
| Profile | `[profile.release]` — `panic=abort`, `lto`, `strip=symbols`, `opt-level=3` |

Intro package manifest (`INTRO-PACKAGE.txt`) captures version, UTC timestamp, `rustc -V`, toolchain file reference, SHA-256 of each artifact, and verify instructions. Generated by `scripts/release-sign.sh`.

## Cryptographic attestation

Detached signatures cover `lexicon`, `lexicon.cdx.json`, `vendor.tar.gz`, `deny-report.txt`, and `SHA256SUMS`:

- **cosign** (`COSIGN_KEY`) → `*.sig`
- **GPG** → `*.asc`

Recipients verify hashes first, then signatures. Key custody is the adopter's — publish cosign/GPG public keys through your program office, not through this repo unless your release policy says otherwise.

## Runtime data provenance

| Artifact | Provenance |
|----------|------------|
| `names.sqlite` | Append-only event chain; Merkle root + optional signed snapshot |
| `bindings.sqlite` | Separate classified chain when policy enables persistence |
| Authority keys | `<data-dir>/keys/<agency>.json` — local generation; rotation via `key rotate` events |
| Mint proofs | VRF proof + beta in minted-name JSON; verifiable with authority public key |

Event signatures bind canonical event bytes (not the signature blob). Issued events on the names chain use U-only canonical bytes; binding fields hash on the bindings chain when open.

Attribution (when enabled) is an OS-session claim (`whoami`, hostname, machine-id) — not PIV/CAC attestation. See [SECURITY.md](../SECURITY.md).

## Reproducibility

Rust release binaries are not fully reproducible across OS/libc/linker without pinning the entire build image. The intro package workflow expects:

1. Hash match of **staged** `dist/lexicon` to `SHA256SUMS`, and/or
2. Air-gap rebuild from vendored sources with the same toolchain and features, then compare hashes.

Document the builder OS, target triple (`x86_64-unknown-linux-gnu` vs `musl`), and feature flags in your accreditation package.

## Third-party data

| Dataset | Origin |
|---------|--------|
| Word pools / JANAP table | Bundled in `lexicon-pools`; steward edits bump `POOL_ID` |
| `historical_cryptonyms.txt` | Public sources (Wikipedia-derived list in repo); header documents scope |
| `crosswd.txt` | Crossword dictionary for pool construction |
| Reject lists | Curated; `historical` and `military` sets |

Do not treat bundled reject lists or SCI registers as operational intelligence.

## Incident trace-back

1. Identify `lexicon` binary hash and intro package signature date.
2. Map to git tag/commit and `Cargo.lock` from the same build.
3. For ledger issues, export `names` (and `bindings` if accredited) JSONL with banners; verify Merkle chain and signatures with `ledger audit`.
4. Cross-check pool `POOL_ID` printed by `pool inspect` against the built binary.
